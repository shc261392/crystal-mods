# Unity font build — Iansui SDF

Produces `plugin/bundles/tcserif`, the TMP font asset the BepInEx plugin loads.

## Why Unity at all

Black Book renders Chinese from **static SDF atlases baked from its own
Simplified text**, so its fonts contain no glyphs for the characters that differ
in Traditional Chinese. A replacement font asset therefore has to be built, and
TMP font assets cannot be produced without the Unity Editor:

- `Font.CreateDynamicFontFromOSFont` gives a Font with **no embedded font data**,
  so `FontEngine.LoadFontFace` fails and `TMP_FontAsset.CreateFontAsset` returns
  null. Registering the TTF with the OS is not enough.
- UnityPy cannot create Font bundles — `get_writeable_cab()` is only a byte
  writer, with no way to add objects.

So `plugin/bundles/tcserif` is a **committed build artifact**, generated by
Unity **2018.4.31f1 (changeset `212ea663d844`)** — byte-identical to the engine
that built the game, which keeps the asset format compatible with the game's
TMP.

## Font choice

[Iansui 芫荽](https://github.com/ButTaiwan/iansui) v1.020, **SIL OFL** — a
Traditional Chinese face designed for zh-TW. 10,017 CJK ideographs and complete
Cyrillic coverage, so the game's Latin and Russian UI render from it too.

Noto Serif TC was tried first (matched the game's Noto Serif SC family) but an
SC and a TC cut of the same family still read as two different fonts.

## Build

Requires the Unity Editor (see the main README) and `fontTools`.

```bash
# 1. download Iansui, subset it to the characters the game uses
python3 ../scripts/build_font.py
#    -> Assets/Fonts/Iansui-Regular.ttf  (generated, gitignored)
#    -> Assets/Fonts/charset.txt

# 2. build the asset + bundle (staged to a Windows-visible path; the repo lives
#    on the WSL filesystem, which Unity cannot read)
cp -r . /mnt/d/Unity/tcfont-project/
"/mnt/d/Unity/2018.4.31f1/Editor/Unity.exe" -batchmode -quit -nographics \
    -logFile "D:/Unity/unity-build.log" \
    -projectPath "D:/Unity/tcfont-project" \
    -executeMethod BuildTcFont.Build

# 3. copy back
cp /mnt/d/Unity/out/tcserif ../../plugin/bundles/tcserif
```

`Assets/TextMesh Pro/` is TMP's *Essential Resources* — the shaders live there,
not in the package, and `CreateFontAsset` throws `ArgumentNullException: shader`
without them. It was extracted from
`Library/PackageCache/com.unity.textmeshpro@1.5.0/Package Resources/TMP Essential Resources.unitypackage`
(a plain tar.gz) because TMP's own importer calls `ImportPackage(..., true)`,
which blocks a batch build.

## Notes that cost time to discover

- **TMP 1.5.0 is required.** 1.4.1's `TryAddCharacters` is broken: it dereferences
  a null `Glyph[]` (TMP_FontAsset.cs:1242) and crashes with
  `ArgumentException: An item with the same key has already been added` on
  codepoints that share a glyph. 1.5.0 supports Unity 2018.3+.
- **One codepoint per glyph.** `scripts/build_font.py` dedupes by glyph, because
  TMP 1.4.1/1.5.0 does a bare `m_GlyphLookupDictionary.Add(glyphIndex, glyph)`
  and compatibility forms would collide.
- **Point size and padding matter for weight.** The asset is built at the game's
  own settings (`24 pt, padding 5, SDFAA`), read from its `NotoSerif` atlas, so
  stroke weight matches.
- **The atlas must be pre-sized.** TMP creates it as 0x0 and resizes lazily; if
  that resize does not take, native packing returns null glyphs.
- **Atlas is 4096²**, not the game's 2048², because TMP 1.5.0's programmatic path
  produces a single atlas and ~4,330 glyphs do not fit in a 2048 tile.
