# Battlesector v1.7.4 asset migration research report

**Date:** 2026-07-03
**Old export (previous ground truth):** `/mnt/d/mods/battlesector/ExportedProject` (AssetRipper, Unity 6000.0.62f1)
**New export (v1.7.4 — new ground truth):** `/mnt/d/mods/battlesector-v1-7-4/ExportedProject` (AssetRipper, Unity 6000.0.62f1)
**Scope:** Identify every game-data change in the v1.7.4 update that affects the
Battlesector Tools site / mod data, apply the changes (new = ground truth), and
document everything (including changes with no site impact).

---

## 1. Method

A naïve "hash every file and diff" of two AssetRipper exports is **dominated by
noise**: AssetRipper regenerates a fresh `.meta` GUID for every asset on each
export (verified: `FactionDataTable.asset.meta` guid `7ef4aabf…` → `7a155244…`),
and every `.asset` that references another asset by GUID therefore changes even
when the underlying game data is identical. A raw content-hash diff of the
`MonoBehaviour/*.asset` tree flags tens of thousands of files that carry **zero**
semantic change.

To get signal instead of noise the comparison used three layers:

1. **Data tables** (`MonoBehaviour/*.asset`, Unity YAML) — GUID/`fileID`
   references normalized out, then diffed; and the site's extraction pipeline
   (`parse_stat_assets.py`) re-run against the new export so the derived
   `units_complete.json` / `weapons_complete.json` could be diffed field-by-field.
2. **Text repositories** (`Resources/text_repository-*.txt`, plain UTF‑8) —
   diffed directly (no GUID noise).
3. **Images** (`*.png`) — content-hash compared. PNG encoding is **byte-stable**
   across the two exports (verified on unchanged HUD icons: 5/5 identical hashes),
   so a hash difference is a real pixel change, not a re-encode artifact.

Both trees were fully hashed (`hash_tree.py`, excluding `.meta`) for the raw
inventory in the appendix; the categorized findings below are the filtered,
semantically-meaningful result.

## 3. Unit stat / data changes (site-relevant)

Unit count unchanged: **190 → 190** (no units added or removed). Weapon count
unchanged: **442 → 442**. After GUID normalization, only two site-visible units
changed:

| Unit | id | Field | Old | New |
|---|---|---|---|---|
| **Terminators** | 11009 | `pointCost` | 200 | **220** |
| **Storm Speeder** | 11014 | `isLarge` | false | **true** |

Additional unit-table edits that do **not** surface on the site (documented for
completeness):

- **Unit 999** ("Unknown Unit 999"): lost ability `80020` and one weapon slot.
  This entry is filtered out of the site (placeholder/"Unknown" name), so no
  impact. Confirmed absent from `units.json`.
- **Terminators / other units**: several `loadout_slots` variant `PointCost`
  edits (e.g. Terminators Flamer/Assault variants `0 → -20`) and `ULT_*` upgrade
  slot reference swaps. The site consumes `weaponSlots` + `abilityIds`, **not**
  `loadoutSlots`, so these are not shown.
- Assorted `MeleeReactWeapon`, `Keywords`, weapon-slot reconfiguration on a few
  units — not exposed by the site schema.

No changes to any core stat value (`MaxHealth`, `Armor*`, `Evasion`,
`MaxActionPoints`, `MaxMovementPoints`, `MeleeAccuracy`, etc.) on any unit.

### Applied
- `complete_stats/units_complete.json` (+ `.csv`) regenerated from the v1.7.4
  export (local ground-truth extract in `.copilot_workspace`, gitignored).
- `src/data/units.json` — **surgical** edits of the two fields above, preserving
  the injected `portrait` mapping (a full pipeline re-run would drop it — see
  `patch_weapon_mechanics.py`). Verified: exactly 2 field changes, portraits intact.

## 4. Weapon changes

`WeaponDataTable.asset` differs only in `ProjectileEffect` values on 7 weapons
(e.g. `10028 → 11011`, `18 → 11012`). `ProjectileEffect` is a **VFX reference**,
not a gameplay stat, and is **not** part of the site's weapon schema. Re-running
the extractor and diffing the derived `weapons_complete.json` (GUID-normalized)
reported **0 changed weapons**. `weapons.json` was left untouched to avoid
needless `custom_icon_guid` churn (which would require regenerating the weapon
icon GUID map).

## 5. Other data tables

- **FactionDataTable** (+184 lines): every command-bark entry gained an **empty**
  `audioClip` block (`m_AssetGUID`/`m_SubObjectName`/`m_SubObjectType`, all blank)
  — a schema addition, no data change. Faction names/slogans/colors unchanged.
- **UnitDataTable** (+13,271 lines): ~9,669 lines are the same empty `audioClip`
  schema field; the remainder is **new voice-bark data** (audio clips + bark
  text/ability triggers). Audio only — no stat impact.
- **AbilityDataTable, RoleGroupDataTable, WarzoneUpgradesDataTable:** no semantic
  change.
- **StatusEffectDataTable:** one status effect's `TooltipDescription` text id
  changed `1665 → -1` (tooltip removed). Text id `1665` is not referenced anywhere
  in `src/data` (including `buffs.json`), so no site impact.

## 6. Text / localization changes

Comparing `Resources/text_repository-*.txt` between exports:

- **English:** the only change is `text_repository-default-external.txt` id `40`
  `Warzone` → `Crusade` ("Warzone selector label"). This lives in the
  *default-external* repository (map editor / mod.io UI), which the site does not
  consume, and the internal `WarzoneUpgradesDataTable` is unchanged — no site impact.
- **Chinese (major):** the game's bundled Chinese switched from **Traditional
  (繁體)** in the old export to **Simplified (简体)** in v1.7.4 across all Chinese
  repositories (`units`, `units-external`, `default`, `default-external`,
  `campaign*`, `barks`). Examples: `聖血天使 → 圣血天使`, `勢能 → 势能`,
  `終結者 → 终结者`, `風暴速攻艇 → 风暴速攻艇`.

  The old export's Chinese was Traditional (identical to the repo's previously
  extracted `text_repository-*_chinese.txt`); the clean v1.7.4 export ships proper
  Simplified. The site's **zh‑CN** locale is derived directly from these game
  repositories, so it was previously showing (mislabeled) Traditional characters.
  Updating to v1.7.4 corrects zh‑CN to genuine Simplified. The site's **zh‑TW**
  locale is derived from the repo's TC-localization mod source (unaffected).

### Applied
- `extracted_text_assets/` (gitignored local extract): the 8 changed repositories
  copied from the v1.7.4 export.
- `src/data/i18n.json`: the **zh‑CN** name sections regenerated to Simplified —
  147 unit names, 393 weapon names, 11 faction names, 7 role names (558 total).
  **zh‑TW was preserved** (the TC-mod source did not change; a full regen would
  have introduced unrelated OpenCC-version drift such as `鐳射→雷射`, which was
  deliberately excluded to keep this migration strictly game-derived).

## 7. Image changes

### 7a. Ability / command icons (`public/ability-icons/`, 454 files)

Comparing all 454 shipped ability icons against both exports by basename
content-hash: **440 identical, 14 changed art** (0 removed). The 14 are Adepta
Sororitas / command-ability icons redesigned in v1.7.4 (same 256×256 dimensions;
byte size grew ~8 KB → ~90 KB, i.e. more detailed art, not a resolution change):

`CatechismOfFireIcon`, `JumpPackAssaultIcon`, `LitanyOfHateIcon`,
`LitanyOfHateFinalizedIcon`, `MantraOfStrengthIcon`, `OathOfProtection`,
`PurgeTheHereticsIcon`, `ReclamationForceStatusIcon`, `SmokeGrenadeIcon`,
`SpiritualLeaderIcon`, `TacticalRepositionStatusIcon`, `TerrorTroopsIcon`,
`TheImperiumSwordIcon`, `UnyieldingInTheFaceOfTheFoeIcon`.

**Applied:** the 14 PNGs were refreshed from the v1.7.4 export into
`public/ability-icons/`. Caveats: (1) `public/ability-icons/` is **untracked**
in git, so this is local ground-truth staging — the live site only picks these up
via an R2 re-upload / redeploy; (2) `ability-metadata.json` does not currently
reference these command-icon filenames, so they may be presently unreferenced.

### 7b. Site-referenced images (`image-urls.json`)

Of the **1,370** image names referenced by the site (`image-urls.json`: 520
units, 570 weapons, 280 factions), content-hash comparison found:

- **1,356 identical.**
- **0** unit portraits, weapon icons, faction icons, or HUD/stat icons changed.
- **6 changed** — Ork **Deff Dread** 3D model PBR texture maps
  (`ORK_DEF_Arms_AO/_D/_S`, `ORK_DEF_Body_AO/_D/_S`, from `sharedassets41.assets`).
  These were bulk-uploaded to R2 under the `units` category but are **not
  referenced by any unit `portrait` or weapon `icon`** on the site (the Ork
  weapon icons actually shown, e.g. `UI_WPN_ORK_DEF_Shoota`, are unchanged). So
  this is a real in-game model re-skin with **no site impact**.
- `HaywireMineIcon` (unit 11022 portrait) was not extracted as a PNG in the new
  export (present as anim/avatar/config only). The unit is otherwise unchanged and
  the R2 copy persists → **no action**; treated as an export-scope artifact.
- 7 atlas textures (`ConquestResourceIconsAtlas_*`, `UpgradeIconsAtlas-*`, `Knob`)
  are not standalone PNGs in **either** export (sprite atlases) — pre-existing, not
  a v1.7.4 change.

**No image re-uploads or `image-urls.json` changes are required.**

> Note on export completeness: the v1.7.4 export contains fewer loose textures
> overall (`Texture2D` 17,090 → 9,526 files; `Sprite` 5,104 → 3,332) because of
> different AssetRipper extraction scope, **not** because the game removed art.
> Weapon icons, for example, live under `Assets/UI/WeaponIcons/` and are fully
> present (1,544 → 1,548 `UI_WPN_*` files). Absent files must not be deleted from R2.

## 9. Reproduction

- `normdiff.py` — GUID/`fileID`-normalized diff of two `.asset` files.
- `regen_stats.py` — re-run `parse_stat_assets.py` against an arbitrary export.

- `apply_migration.py` — surgical `units.json` + zh‑CN `i18n.json` edits.
- `manifest_diff.py` — categorize the raw full-tree manifest diff.

## Appendix A — raw full-tree hash inventory

Both `ExportedProject/Assets` trees were fully hashed (excluding `.meta`):

- OLD: **83,195** files · NEW: **85,148** files.
- Raw path-keyed diff: **19,172 added · 17,219 removed · 39,874 content-changed.**

This raw diff is **not** a game-change list — it is dominated by export-tooling
noise and must not be used directly:

- **Per-export GUID regeneration** rewrites every `.meta` and every GUID/`fileID`
  reference inside `.asset` files (hence ~40k "changed" `.asset`/`.mat`/`.prefab`).
- **Folder reorganization / case changes** between exports turn identical content
  into add+remove pairs, e.g. `Audio/` (4,437 removed) vs `audio/` (4,798 added),
  and `Config/` (4,419 removed vs 4,420 added).
- **Different extraction scope**: `Texture2D` 3,816 removed / 34 added, `Sprite`
  903 removed / 17 added — the new export simply extracts fewer *loose* textures
  (UI art moved under `UI/`, still present). No game art was deleted.

The only high-signal slice of the raw diff is same-path PNG content changes (15),
all reconciled above: 3 font atlases (irrelevant to the site) + 11 command/status
icons + (via basename matching) 3 more → the 14 ability icons in §7a and the 6 Ork
model textures in §7b. Every semantically meaningful change is captured in §§3–7.
