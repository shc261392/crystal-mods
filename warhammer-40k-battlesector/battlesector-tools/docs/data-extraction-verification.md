# Data Extraction & Verification

## Purpose

Documents the complete data flow from game assets → extracted data → website data, including verification methodology for investigating data accuracy claims.

## Data Pipeline

### 1. Source: Unity Game Assets (AssetRipper Export)

**Location**: `/mnt/d/mods/battlesector/ExportedProject/Assets/MonoBehaviour/`

**Key Files**:
- `UnitDataTable.asset` (2.0 MB Unity YAML) - All unit stats, weapon slots, ability assignments
- `WeaponDataTable.asset` - All weapon stats
- `AbilityDataTable.asset` - Ability ID → GUID mappings

**Format**: Unity YAML with MonoBehaviour objects

**Example Structure**:
```yaml
MonoBehaviour:
  m_Name: UnitDataTable
  keys: ee030000... # Hex-encoded unit IDs (4-byte little-endian)
  values:
  - Disable: 0
    Faction: 2
    ShortNameID: 196
    LongNameID: 197
    PointCost: 60
    Members: 5
    MaxHealth: 50
    AbilityList:  # ← Direct ability assignments
    - Ability: 12
      StartsLocked: 1
    - Ability: 20001
      StartsLocked: 0
    WeaponSlots:
    - Weapons:
      - Weapon: 2000
        PointCost: 0
        StartsLocked: 0
```

### 2. Extraction Scripts

**Location**: `../../.copilot_workspace/battlesector-data/*.py`

**Key Scripts**:

1. **`parse_stat_assets.py`** - Reads Unity YAML, extracts unit/weapon stats
   ```python
   # Line 220: Direct extraction without transformation
   'ability_list': unit.get('AbilityList', [])
   ```

2. **`parse_ability_assets.py`** - Extracts ability stats from individual ability assets

3. **`prepare_website_data.py`** - Generates clean JSON for website
   - Resolves localization IDs to names
   - Converts to website-friendly format
   - No filtering or transformation of ability assignments

**Output**: `../../.copilot_workspace/battlesector-data/complete_stats/*.json`

### 3. Website Data

**Location**: `src/data/*.json`

**Key Files**:
- `units.json` - Unit stats with resolved names
- `weapons.json` - Weapon stats
- `factions.json` - Faction data
- `i18n.json` - Multilingual localization

**Processing**: Generated by `prepare_website_data.py` via `pnpm run generate:data`

## Verification Methodology

### Case Study: Ability #20000 Investigation

**User Claim**: "Game help text indicates ability #20000 should be available to more than Battle Sisters"

**Investigation Process**:

#### Step 1: Check Raw Unity YAML
```bash
# Search for ability in source YAML
cd /mnt/d/mods/battlesector/ExportedProject/Assets/MonoBehaviour
grep -n "    - Ability: 20000" UnitDataTable.asset

# Result: 2 occurrences
# Line 11140: Real assignment in AbilityList
# Line 11425: Voice bark configuration (not an assignment)
```

#### Step 2: Extract Context
```bash
# View unit definition around line 11140
sed -n '11063,11150p' UnitDataTable.asset

# Result: Unit with LongNameID 197, DefaultModel 2006
# AbilityList contains: [12, 20001, 20033, 20000]
```

#### Step 3: Resolve Unit Name
```bash
cd ../../.copilot_workspace/battlesector-data
grep "^197|" extracted_text_assets/text_repository-units.txt

# Result: 197|Adepta Sororitas Battle Sisters|Unit Type Long|Unit
```

#### Step 4: Verify Complete Stats
```bash
cd ../../.copilot_workspace/battlesector-data
python3 -c "
import json
data = json.load(open('complete_stats/units_complete.json'))
units_with_20000 = [u for u in data 
                    if any(a.get('Ability') == 20000 
                          for a in u.get('ability_list', []))]
print(f'Units with ability 20000: {len(units_with_20000)}')
for u in units_with_20000:
    print(f'  - {u[\"unit_id\"]}: {u[\"name\"]}')
"

# Result: 1 unit - "Adepta Sororitas Battle Sisters" (ID 2006)
```

#### Step 5: Verify Website Data
```bash
cd ../../battlesector-tools
python3 -c "
import json
units = json.load(open('src/data/units.json'))
units_with_20000 = [u for u in units if 20000 in u.get('abilityIds', [])]
print(f'Website units with ability 20000: {len(units_with_20000)}')
"

# Result: 1 unit
```

### Findings

**Conclusion**: Only **1 unit** in the entire game has ability #20000 assigned to it in the base game data.

**Data Flow Integrity**: ✅ VERIFIED
- Raw YAML → Complete Stats: Exact match
- Complete Stats → Website Data: Accurate transformation
- No filtering or omissions in pipeline

**If Help Text Claims Otherwise**:
1. Help text may be incorrect/outdated
2. Ability may be granted through gameplay mechanics (not in UnitDataTable)
3. Separate ability-granting system may exist outside base unit stats

## Data Integrity Principles

### 1. Truth-Grounding Hierarchy

When conflicts arise, follow this precedence:

1. **Raw Unity YAML** (`/mnt/d/mods/battlesector/ExportedProject/`)
   - Source of truth for game mechanics
   - Directly extracted from compiled game

2. **Complete Stats** (`../../.copilot_workspace/battlesector-data/complete_stats/`)
   - First derivation from raw YAML
   - Minimal transformation (name resolution only)

3. **Website Data** (`src/data/`)
   - Second derivation for web consumption
   - Clean format, no mechanical changes

4. **Game Manual PDF** (conceptual reference only)
   - Not a numeric/mechanical authority
   - May contain errors or outdated information

### 2. Verification Checklist

When investigating data discrepancies:

- [ ] Search raw Unity YAML for the data point
- [ ] Check extraction script logic (no filtering?)
- [ ] Verify complete_stats matches raw YAML
- [ ] Confirm website data matches complete_stats
- [ ] Document line numbers and exact YAML content
- [ ] Provide reproducible verification commands

### 3. Documentation Requirements

All data investigations must include:

1. **Raw Source Evidence**: Line numbers, YAML excerpts
2. **Extraction Script Path**: Which script processes this data?
3. **Verification Commands**: Reproducible bash/python commands
4. **Data Flow Diagram**: Source → Complete → Website
5. **Conclusion**: Clear statement of what the raw data says

## Common Pitfalls

### ❌ Wrong: "The data seems incomplete"
- Vague claim without source verification
- No reproducible investigation

### ✅ Right: "I verified in UnitDataTable.asset lines 11063-11150 that only unit 2006 has ability 20000"
- Cites exact raw source
- Provides line numbers
- Reproducible

### ❌ Wrong: "The manual says X, so our data must be wrong"
- Reverses truth hierarchy
- Manual is conceptual aid, not mechanical authority

### ✅ Right: "The manual says X, but UnitDataTable.asset shows Y. Raw data takes precedence."
- Follows truth-grounding hierarchy
- Documents both sources
- Clear resolution
